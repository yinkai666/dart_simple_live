# iPad 播放性能与退出排查记录

已知现场：斗鱼普通单直播，iPadOS 16.6.1；有时逐渐卡顿至断流，刷新可恢复；另有自动退出反馈。没有 iPad 型号、原生崩溃报告或进程内存曲线，因此本记录不能作为实际闪退根因结论。

## 本轮确认并修复

| 风险 | 证据与处理 |
| --- | --- |
| 图片缓存只限制条数 | 源图和合成位图分别增加 16 MiB 的 RGBA 字节预算，超限释放缓存句柄。 |
| 合成位图尺寸及缓存命中并发无上限 | 合成单图限制 2 MiB、单边 4096 物理像素；最多 32 个并发合成任务。过载回退文本，不追加无限等待。 |
| 活跃 canvas 图不属于缓存预算 | 入场和替换前单独核算活跃位图 16 MiB 预算；替换时减去旧图字节，保留 clone 独立所有权。 |
| 纯文本图仍可能过大、突发绘制过多 | 位图生成前使用 canvas_danmaku 同一段落构造器测量；检查字号、描边、DPR、长度、边长与字节数。每个弹幕层每秒最多接受 24 次绘制任务，超额屏幕弹幕丢弃，聊天区仍保留正常消息。异常超过 2048 字符的入站消息在正则、历史和 FFI 前拒绝。 |
| Android 解码参数可误用到 iOS | 兼容模式的 mediacodec 参数现在限定 Android，iOS 使用正常硬解路径。 |
| 后台断流事件被丢弃 | 后台只记录待恢复状态，回前台处理；不在后台发起自动取地址。 |
| 重试等待阶段的暂停被覆盖 | 暂停意图覆盖整个重试等待、取地址和排队过程，换台与退出清理监听。 |
| Rust 异常配置可产生零除或零步长循环 | 归一化桶数量和间隔；构造不变量测试先失败后修复。通常需要异常导入配置或直接调用，不是当前用户场景的已知根因。 |
| 长时间挂起后逐桶循环成本过高 | 跨越完整窗口时一次清空，并用取模推进，保持时间对齐。接近 u64 最大值的时间跳变测试立即结束。 |

这些预算分别约束具体资源，不是整个应用内存上限。Flutter 自带图片缓存、视频解码器、视频纹理和其他模块仍占用内存。默认最高清晰度未改动。

## 已核对的路径

- canvas_danmaku 的过期、清空与销毁路径会释放图像句柄，未发现已交接克隆必然泄漏的证据。
- Rust dispose 已等待在途批处理，播放器关闭流程不会被该释放异常阻断。
- Release 模式不往应用的调试消息列表持续追加日志，该列表不能直接解释 Release IPA 的内存增长。
- 定时关闭确实会主动退出进程；它与原生崩溃不同，仍需核对用户设置及退出时刻。
- 显式双重缓存沿用磁盘缓存语义，存在随媒体播放持续追加文件的既有行为；默认 iPad 短缓存为内存模式。

## 验证

- 表情图片渲染：31 项 Flutter 测试通过。临时环境只替换日志模块，生产 renderer 与测试源保持一致；不替代完整应用或实机测试。
- 绘制入场限制：3 项 Flutter 测试通过，覆盖突发上限、正常文本和异常尺寸。
- Rust：6 项 cargo 测试通过，覆盖零参数、部分过期、整窗过期和极长时间跳变。
- 恢复策略：独立 Dart 检查通过，包含后台事件与跨等待的暂停意图。
- iPad Actions 增加上述检查后再构建，保留独立安装标识。
